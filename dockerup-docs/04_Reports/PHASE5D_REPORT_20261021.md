日期：2026-10-21 ・ 環境：本機 `wifi-local`（http://10.88.90.136:8000） ・ **未部署**

## 1. 結論

- **上傳 Log 改為三步驟精靈**（Q16）：① 選擇 log → ② 確認 → ③ 結果，一次只顯示目前這一步；做完的步驟收成一行摘要（檔名、份數、台數、PASS / FAIL、已在資料庫幾份），可展開看細節或「重新選擇」。說明文字收進「使用說明」。
- **表單為主、旁邊是助理**（Q17）：助理用**規則**對照檔名推斷的產品 / 工單與你填的值（不一致會提醒並給「用 X」按鈕）、已在資料庫的份數、這張工單的計畫數、還有幾個錯誤 / 警告；**不呼叫 LLM**。要 AI 對話時按「使用 AI 對話」才開（每回合 2 次 LLM 呼叫）。
- **帶出已設定的計畫數**（Q4）：工單已有計畫數（管理者設的，或之前上傳時填的）時，計畫數欄下方顯示「這張工單已設定計畫數 300（管理者 qc 設定，10/20）」與「沿用 300」按鈕；不會偷偷幫你填，填了不同的值仍會出現「計畫數將更新」的提醒（R15）。
- **結果頁**：新增 / 略過 / 錯誤 / 取消四格；「**這批 vs 該產品歷史**」（良率對門檻與歷史、2.4G / 5G 中位數比平常低多少、主要失敗現象，規則判讀）；需要時按「AI 說明」由 LLM 寫 2–3 句（數字不在事實裡的句子會被刪掉）；「查看工單 5101-…」直接進工單詳情；上傳下一批、撤銷、逐檔結果 CSV / TXT。
- **上傳紀錄精簡**：時間、工單（可點進詳情）、產品、來源、結果（新增 · 略過 · 錯誤）、狀態、上傳者（管理者才看到）、操作。
- **資料庫維護三項**（Q19）：**刪除前影響預覽**（刪掉幾筆、幾台、幾筆來自網頁上傳、連帶移除幾筆失敗分類 / 處置 / RD 分析、每張工單刪除前後的台數與良率；刪整張工單還要輸入工單號確認）、**匯出 CSV**（目前篩選的資料，不含原始 log）、**依上傳批次撤銷**（新分頁「上傳批次」）。每列兩顆按鈕改為一個「⋯」選單。

## 2. 細節

- 強制按「上傳」而伺服器拒絕時（例如工單號格式錯），畫面回到第 ② 步，把伺服器的錯誤放在檢查清單最上面，改完可以直接再上傳；不會停在結果頁。
- 「這批 vs 該產品歷史」比的是這個產品在資料庫裡的其他機台（不含這一批）。實測：一批 252 台、良率 100%，2.4G 中位數 15.5 Mbps 比平常 19.7 低 21%（超過設定的 20%）→ 黃燈提醒；5G 84.2（平常 91.6）正常。
- AI 說明的句子切分修正：原本會把「15.5」切成「15.」與「5…」兩句，整段變得不通順；現在只在句號、問號、驚嘆號（英文後面要有空白）斷句。
- 影響預覽用的是和刪除同一個條件，所以預覽的筆數就是實際刪掉的筆數。
