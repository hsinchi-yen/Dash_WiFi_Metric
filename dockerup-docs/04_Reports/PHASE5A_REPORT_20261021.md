## 2. 做了什麼

**工單頁**
- 「基本欄位」(預設,9 欄):狀態、工單、產品、已測 / 計畫、良率、FAIL、狀態說明、最後測試、AI 報告。
- 「全部欄位」(15 欄)另加 PASS、重測率、2.4G、5G、歷時、台 / 時(實際 / 目標)。選擇會記住。
- 狀態:進行中(2 小時內有測試)、暫停中、已完成(24 小時沒有測試,或已達計畫數)。燈號:紅 / 黃 / 綠,紅黃列左邊有色條。滑鼠停在燈號上會列出觸發的檢查。
- 狀態說明:AI 寫的一句話(標「AI」);AI 還沒寫好或離線時顯示規則寫的同一句話。
- 狀態以**整張工單**計算,不受日期篩選影響(頁面下方有說明)。

**狀態規則**(伺服器,`services/wo_rules.py`,純函式可單元測試)

| 檢查 | 燈號 | 預設 |
|---|---|---|
| 良率低於黃色門檻 | 紅 | < 95% |
| 良率低於綠色門檻 | 黃 | < 98% |
| 連續 FAIL(不同台,依測試順序) | 紅 | ≥ 3 台 |
| 2.4G / 5G 吞吐量中位數比同產品平常低 | 黃 | ≥ 20%(30 台以上才比) |
| 進行中且上班時間內,近一小時台數低於每小時目標 | 黃 | ≥ 20% |
| 超過計畫數 / 已達計畫數 | 資訊 | — |
| 不到 10 台 | 資訊(良率暫不判斷) | — |

「同產品平常」= 該產品**其他**工單的中位數(至少 2 張、每張 20 台以上)。每小時目標預設用同產品平常速度(**每個有測試的小時的台數**中位數,TN-86 為 54.1),可在設定頁依產品覆寫(Q15)。

**AI 一句話(L1)**
- 規則先決定狀態、燈號與檢查結果;LLM 只把它寫成一句中文 + 一句英文(**一次呼叫產生雙語**,Q24)。
- **數字只准來自事實**(Q26):句子裡每個數字都要對得上事實,否則丟掉、改用規則句。2.4G / 5G 的頻段名稱例外。
- 事實沒變就不重寫;資料、狀態或設定改了才重寫。進行中的工單優先。背景執行,與 AI 報告共用同一個 LLM 佇列,一句約 2–4 秒,77 張第一次約 5 分鐘。
- LLM 離線或逾時:立刻用規則句,5 分鐘後再試。

**設定頁**(管理者,側欄「設定」)
- 良率門檻(含顏色預覽)、上下班時間(單班,Q3)、進行中 / 已完成的時間、三個檢查的門檻、各產品每小時目標。
- 只送出有變的欄位;伺服器檢查範圍(例如黃色門檻必須低於綠色),錯誤欄位標紅。
- 每次儲存記在帳號管理的異動紀錄(例如 `yield_good: 98.0 → 99.5`)。
- 儲存後所有頁面在一分鐘內換成新門檻。

**其他**
- 介面語言預設依瀏覽器語言;網址帶 `?lang=zh` 一律中文(大電視用,Q6)。
- AI 報告的門檻改用設定頁的 98 / 95(原本寫死 99.2 / 98.5)。已存在的報告不會因此重寫,5B 會整批換成新的結構化報告。

## 5. 過程中發現並修正的問題

| # | 問題 | 修正 |
|---|---|---|
| 1 | 兩個 API 行程各自快取設定 5 秒;儲存時拿「快取」比對,連續兩次修改時第二次可能被當成「沒變更」而**沒存進去**(驗收測試抓到) | 儲存時改為在同一個交易裡加鎖、直接讀資料庫比對 |
| 2 | 數字核對永遠允許「1」,AI 自己算的「不良率 1.0%」會過關 | 只允許事實裡的數字與頻段名稱 |
| 3 | AI 照抄規則句,或單位混用「件 / 台」、全形半形標點混用、同一句重複良率 | 提示詞規定語序、單位、標點、每個數字只寫一次;規則句同步改成全形標點 |
| 4 | 報告提示詞的單元測試有一項在本階段之前就失敗(中文 carousel 報告已改成全中文標題,測試仍期待英文標題) | 測試改為檢查全中文標題 |

## 6. 請你確認的預設值

- 上班時間 07:00–19:00、2 小時內有測試算「進行中」、24 小時沒測試算「已完成」。
- 連續 3 台 FAIL 為紅;吞吐量比平常低 20%、近一小時比目標少 20% 為黃。
- 「平常速度」用每個有測試的小時台數的中位數(不用首尾時間差,那會把夜間空檔算進去,TN-86 會變成 14 台 / 時)。

這些都能在設定頁直接改,不需要改程式。
